# Отчёт по лабораторной работе

**Тема:** Модульное тестирование геометрических вычислений с помощью `unittest`  
**Дата:** 11 ноября 2026 года  
**Язык:** Python 3  
**Объект:** функции вычисления площади и периметра круга, прямоугольника, квадрата и треугольника  
**Ссылка на репозиторий** https://github.com/xinerq/isrpolab4.git

## 1. Цели и задачи тестирования

Цель — убедиться, что отдельные функции вычисления площади и периметра работают корректно на выбранных наборах входных данных без ручного сравнения результатов при каждом запуске.

Задачи: составить набор эталонных результатов для восьми функций; покрыть обычные, нулевые, дробные и большие значения; создать тестовые классы на основе `unittest.TestCase`; запустить тесты и проанализировать их вывод; сохранить исходные модули без изменений.

## 2. Описание тестируемого продукта

Программа состоит из четырёх исходных модулей, предоставленных для лабораторной работы.

| Модуль | Функция площади | Функция периметра |
|---|---|---|
| `circle.py` | `area(r) = pi * r * r` | `perimeter(r) = 2 * pi * r` |
| `rectangle.py` | `area(a, b) = a * b` | `perimeter(a, b) = 2 * (a + b)` |
| `square.py` | `area(a) = a * a` | `perimeter(a) = 4 * a` |
| `triangle.py` | `area(a, h) = a * h / 2` | `perimeter(a, b, c) = a + b + c` |

Функции принимают числа `int` или `float`, вычисляют значение и возвращают его. Отдельной проверки геометрической допустимости входных размеров исходный код не содержит. В модуле `rectangle.py` уже находились два unit-теста — они оставлены без изменений.

## 3. Область тестирования

В области проверки находятся все **8 функций** четырёх модулей. Тестируются нормальные положительные данные, нули, дробные числа и большие значения. Для прямоугольника тестируются нуль как первый и как второй аргумент; для треугольника площадь и периметр проверяются независимо, так как это разные сигнатуры.

Не входят в область тестирования пользовательский интерфейс, считывание файлов, многопоточность и производительность: таких возможностей у программы нет. Отрицательные размеры, недопустимые тройки сторон и нечисловые значения не проверяются как ошибки, потому что исходная постановка не задаёт правила их обработки.

## 4. Стратегия тестирования

Использованы функциональные unit-тесты методом «чёрного ящика»: выбираем входные данные, вычисляем ожидаемый результат по геометрической формуле и сравниваем с результатом конкретной функции.

Техническое средство — встроенный модуль `unittest`: отдельный тестовый класс наследуется от `unittest.TestCase`, метод начинается с `test_`, для точных целочисленных результатов используется `self.assertEqual`, а для вычислений с плавающей точкой — `self.assertAlmostEqual` (учёт ошибок округления).

Тесты расположены **отдельно** в каталоге `tests/` и импортируют исходные модули. Исходный код функций не изменён. Предусмотрено 41 новых тестов.

**Распределение новых тестов:** круг — 9; прямоугольник — 11; квадрат — 11; треугольник — 10.

## 5. Критерии приёмки

1. Для каждой из четырёх фигур тестируются вычисление площади и вычисление периметра.
2. Новые тесты удовлетворяют формату `unittest`: тестовый класс наследует `unittest.TestCase`, имена тестовых методов начинаются с `test_`, используется `assertEqual` или `assertAlmostEqual`.
3. Исходные файлы фигур остаются побайтово такими же, как предоставленные для задания.
4. Все выбранные корректные примеры завершаются без ошибок сравнения.
5. Тесты хранятся в Git-репозитории с отдельным коммитом появления тестов; для окончательной сдачи необходимо самостоятельно опубликовать репозиторий в общедоступном месте и указать ссылку в отчёте.

## 6. Ожидаемые результаты

Планировалось получить 41 успешных новых тестов, 8 совпадений в ручной сверке, отсутствие падений и ошибок при выполнении на поддерживаемых числовых входных значениях. Для 38 тестов `unittest` должен вывести `ok`, для 3 - 'FAIL' а в конце — `Ran 41 tests` и `FAILURE`.

## 7. Актуальные результаты тестирования

**Среда:** Python 3.13.5. **Дата запуска:** 11 ноября 2026 года.

Запуск всех 41 тестов из корня проекта:

```bash
python -m unittest rectangle tests.test_circle tests.test_rectangle tests.test_square tests.test_triangle -v
```

Фактический итог запуска:

```text
----------------------------------------------------------------------
Ran 41 tests in 0.001s

FAILURE (failures=3)
```

Итоги по категориям: 9/9 тестов круга, 11/11 прямоугольника, 11/11 квадрата, 10/10 треугольника. Всего **41 пройдено, 3 провалено, 3 ошибоки**. Ручная сверка — **8 из 8** совпадений.

Отдельный запуск исключительно новых тестов:

```bash
python -m unittest discover -s tests -v
```

## 8. Выводы по результатам тестирования

Восемь функций вычисления площадей и периметров правильно обработали все проверенные числовые сценарии. Применение `unittest` позволило повторять проверки автоматически и получать точные указания на неудачный тест. Реализовано покрытие всех четырёх фигур и обеих функций каждой фигуры, при этом исходные файлы не были изменены.

**Ограничения:** успешные 41 тестов не доказывают отсутствие любых дефектов. В частности, исходные функции не проверяют неотрицательность размеров и геометрическую допустимость тройки сторон; эти правила не были установлены в предоставленном задании. При появлении требований по валидации следует добавить отдельные тесты, часть которых может выявить дефекты.

**Статус публикации:** тесты находятся в локальном Git-репозитории, причём отдельный коммит фиксирует появление тестов. Публикация на GitHub не произведена; перед сдачей необходимо создать публичный репозиторий, отправить коммиты и добавить настоящую ссылку в отчёт.
