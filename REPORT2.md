# Отчёт по лабораторной работе

**Тема:** Знакомство с CI/CD. Автоматизация модульного тестирования с помощью GitHub Actions  
**Дата:** 13 ноября 2026 года  
**Язык программирования:** Python 3  
**Система автоматизации:** GitHub Actions  
**Ссылка на репозиторий** https://github.com/xinerq/isrpolab4.git

## 1. Цель работы

Изучить основные принципы непрерывной интеграции (CI) и научиться настраивать автоматический запуск unit-тестов при отправке изменений в GitHub. Обеспечить проверку программы в двух операционных системах: Ubuntu и Windows.

## 2. Постановка задачи

На основе проекта предыдущей лабораторной работы необходимо создать файл `.github/workflows/main.yml`, который при каждом событии `push` запускает тесты `unittest` на двух GitHub-hosted runner'ах: `ubuntu-latest` и `windows-latest`. Результаты запусков должны быть доступны на вкладке **Actions** репозитория.

## 3. Описание проекта

Проект состоит из четырёх Python-модулей, вычисляющих площадь и периметр геометрических фигур:

| Модуль | Площадь | Периметр |
|---|---|---|
| `circle.py` | `πr²` | `2πr` |
| `rectangle.py` | `ab` | `2(a+b)` |
| `square.py` | `a²` | `4a` |
| `triangle.py` | `ah/2` | `a+b+c` |

Для проверки функций подготовлены четыре файла `test_circle.py`, `test_rectangle.py`, `test_square.py`, `test_triangle.py`. В них содержится **41 unit-тестов**, проверяющих обычные, нулевые, дробные и большие значения. Тесты написаны с использованием `unittest.TestCase`, `assertEqual` и `assertAlmostEqual`.

## 4. Реализация CI

В каталоге `.github/workflows` создан файл `main.yml` со следующим содержимым:

```yaml
name: Tests

on: [push]

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Run unit tests
        run: python -m unittest discover -s tests -v
```

### Объяснение настроек

- `name: Tests` — имя workflow, отображаемое в GitHub Actions.
- `on: [push]` — автоматический запуск после каждого `push` в репозиторий.
- `jobs.test` — задание, выполняющее тестирование.
- `strategy.matrix.os` — создание двух независимых заданий: для Ubuntu и Windows.
- `runs-on: ${{ matrix.os }}` — выбор операционной системы соответствующего runner'а.
- `fail-fast: false` — при ошибке на одной платформе остальные задания матрицы не отменяются автоматически.
- `actions/checkout@v4` — получение файлов репозитория на runner.
- `actions/setup-python@v5` — установка Python версии 3.12.
- `python -m unittest discover -s tests -v` — поиск и подробный запуск тестов из каталога `tests`.

Таким образом, для каждого `push` GitHub Actions создаёт два задания с одинаковым набором тестов, но разными операционными системами.

## 5. Порядок выполнения работы

1. Подготовлены исходные Python-модули и unit-тесты из предыдущей лабораторной работы.
2. В корне репозитория создан каталог `.github/workflows`.
3. Добавлен файл `main.yml` с событием `push`, матрицей двух операционных систем и командой запуска тестов.
4. Изменения отправлены в ветку `main` репозитория GitHub.
5. На вкладке **Actions** проверено появление автоматических запусков workflow `Tests`.
6. Проанализированы статусы запусков и сохранён скриншот страницы GitHub Actions.

## 8. Вывод

В ходе лабораторной работы изучен механизм непрерывной интеграции на платформе GitHub Actions и создан workflow для автоматического тестирования Python-проекта. Workflow запускается при отправке изменений в репозиторий и настроен на выполнение модульных тестов в двух операционных системах — Ubuntu и Windows.

На предоставленном скриншоте подтверждено выполнение трёх запусков workflow, из которых два завершились успешно, а один — с ошибкой. Последний запуск успешен. Автоматизация позволяет проверять изменения без ручного запуска тестов и быстрее обнаруживать регрессии.

**Ограничение подтверждения:** чтобы окончательно удостовериться в выполнении требования о двух runner'ах, необходимо приложить снимок страницы последнего запуска с отдельными успешными заданиями Ubuntu и Windows.
